## Deviations

1. **Roster scope.** In linked courses the roster lists `kiwi` and `import` rows that are not Kiwi course staff; `activity`-only identities are left to Data health. Standalone courses list every row. `status`, `excluded` and `consent` are filters.
2. **Search in pseudonyms mode** matches the pseudonym prefix and the id only exactly or by prefix, so `ada` does not hit `demo-ada`.
3. **Export `groupIds` filter** uses current membership (§6.0 wording), while group columns report the group at event time.
4. **Free-text scrubbing** in pseudonymized and research files replaces the student's own display name, email and legacy name (≥ 3 chars) with the research id. Raw ids are not substituted inside text (short ids hit ordinary words).
5. **Row counts for streamed exports.** The router reads `body["rows"]` only, so stream responses carry a placeholder `rows` list (never sent) plus an `X-Export-Rows` header. See CR-P1.
6. **`study_session_index`** is computed over the exported rows in time order (≥ 30 min gap).
7. **Exports** are also written to `teacher_actions` (`export`, PII-stripped params). Course package export and import are audited.
8. **Native turns** use `ai_provider = kiwi-native` (registry value) and `policy_label = Kiwi lecture AI`.
9. **Profile assignments** list published homework in the student's audience. In-class exercises appear in timelines, not as gradebook cells.
10. **Archiving a group** deletes its memberships, so history periods close. The FOUNDATION delete trigger stamps `valid_to` with SQLite's clock, not `db.now()`. Archived names stay in exports.
11. **Anonymize and group history:** a snapshot/restore around the `group_members` update keeps the history triggers from inventing periods. `UPDATE OR REPLACE` handles a returning student anonymized twice (newer rows win).
12. **Retention** anonymizes events, chat turns, AI calls, drafts and generated items older than the cutoff that are not yet `anon-*`. `learning_sessions` (derived) are untouched.
13. **`PUT /api/teacher/settings`** rejects changes to `attentionRules`/`topicRules` (INSIGHTS has dedicated endpoints) and unknown keys. Permission is `manageCourse` (instructor only).
14. **Course package:**
    - `assignments.json` carries absolute dates and day offsets from `termStart`. Import re-bases on the target term start when both exist, then applies `shiftWeeks`.
    - The schedule is not imported (it would overwrite settings).
    - AI rule configs are reduced to `ai_policy.platform_default()` keys (or `{"inherit": true}`), and identical heads are skipped.
    - File names are sanitized to the zip-safe charset.
    - If `archiveUnreferencedDefaults` archives this week's chapter, `currentUnitId` moves to the first added chapter, with a warning.
15. **Staff:**
    - Linked-course overrides are created only for users in `kiwi_staff_seen`; a second POST for the same user updates the override.
    - Nobody can change or revoke their own row.
    - Staff keys are only created for standalone courses.
16. **Audit viewer** entries also carry `before`/`after` raw JSON (≤ 4,000 chars). Both are null, and the summary lists only changed field names, in Presentation mode.
17. **UI:**
    - `CourseInfoPanel` moved to its own file (re-exported from `CourseSettingsPage.tsx`).
    - Grading/AI defaults live on the Course info tab.
    - Course settings stays instructor-only (frozen route permission `manageCourse`).
    - The Exports filter panel is collapsible so the export list is above the fold at 1280×860.
    - Roster import maps a `group` header to Condition.

## Open questions

1. **Kiwi identity boundary (§14.6, for the Kiwi maintainers; PEOPLE-12, AU-D4-11, AU-D3-26):**
   1. May the CSS Lab bridge return student emails and the class roster, or must it return opaque UUIDs only?
   2. May it return `User.consent` per student, or should Kiwi filter non-consenting students itself?
   3. Can Kiwi provide a class-bound service credential for scheduled sync, plus deletion tombstones?
   4. Should a grade-passback endpoint exist, or is CSV import the intended path?
   5. Can the App SDK offer an official `setChatAvailability` and per-page `tutoringMode`?
   6. Is mapping `assistant` (`userRole: 'ta'`) to a Lab TA who can grade the intended reading?

   Fallback if the answer is "UUIDs only": set `showEmails=false`, import names by student id (or keep email matching off), and drop `email` from the bridge projection.
2. Earlier `teacher_actions` rows that name a student by raw id (e.g. `roster_update` target `s1`) are not rewritten when that student is anonymized, to keep the audit append-only. Should anonymization also rewrite them to `hash:` targets?
3. Should export `groupIds` filter by membership at event time instead of current membership (research use of conditions)?
4. Retention leaves derived `learning_sessions` rows under the real id. Should the TELEMETRY rebuild re-key them, or should retention delete them?
5. `server/test_ai_rules.py` depends on the environment: it fails when the developer `.env` provides an OpenAI key (AIRULES/INTEGRATION).
