### FOUNDATION-S (server)

Smallest faithful interpretations where the spec was ambiguous against the code:

1. **Backup location.** `backup_once` writes `<db dir>/backups/<db stem>.pre-<tag>-<UTC yyyymmddTHHMMSS>.sqlite3` (= `data/backups/kiwi-lab.pre-…` for the default path) so scratch/test DBs never write into the repo. Tag characters outside `[A-Za-z0-9._-]` become `_` in file names (`legacy-rejudge:judging-v2` → `legacy-rejudge_judging-v2`). A copy is written to `*.partial` and renamed, so an interrupted backup never counts. Directory 0700, file 0600. `backup_once` refuses to run inside an open transaction (`MigrationError`).
2. **"Non-empty database"** = any row in events, assignments, submissions, chat_turns, roster, courses, generation_policies, learning_sessions or kiwi_links. A fresh DB gets no backup.
3. **B2:** `graded_by='pre-0.6'` only for graded rows; `released_at = graded_at` (NULL when ungraded). `grade_events('migrated')` rows: `actor_id='pre-0.6'`, `actor_role='system'`, `status_after='released'`, `created_at = graded_at` (else `submitted_at`). The B5 provenance rule is one function applied to submissions in B2 and re-applied in B5 (idempotent).
4. **B3:** `frozen_at` = MIN(submissions.submitted_at, in-class `answer_submitted` created_at by payload `assignmentId`); version-1 snapshots use `created_by='migration'`, `created_at = assignments.updated_at`; snapshot format = `readers.assignment_snapshot(row)` (full stored questions + settings + `version`).
5. **B4:** missing rows are inserted in first-activity order; if no event carries a name, `submissions.student_name` is used; a name equal to the id is not used as a display name. `created_at = updated_at = now` on existing rows.
6. **`identity.ensure_roster`:** non-empty arguments overwrite stored values (so a teacher import can rename a Kiwi student); `source` never downgrades; `add_event` calls it only for first-seen students. New rows fill the legacy NOT NULL `student_name` with display name, email or id.
7. **Legacy `/api/teacher/policies`:** PUT writes a new `policy_versions` unit version (whole-config replacement starting from the current unit config or the platform default; v0.5.1 validation messages unchanged incl. the CJK rejection on this legacy form) instead of `generation_policies` (now never written). GET, `/api/policy` and `ai.build_request` read the resolved version through `ai_policy.policy()`; an unconfigured chapter still yields the v0.5.1 `DEFAULT_POLICY` values, so behavior is unchanged where nothing was customized.
8. **`contracts.AddEventResult`** gained a trailing optional `created_at` (the v0.5.1 `createdAt` response field). `POST /api/events` answers `{id, createdAt, eventId, status}` — 201 created, 200 duplicate `eventId`.
9. **Baseline `add_event`** keeps v0.5.1 validation (unknown type, payload > 60,000 chars, bad ids → 400) and v0.5.1 names (Kiwi username in linked classes, body `studentName` for demo sessions). v2 envelopes (`schemaVersion: 2`) get clamped client time, `client_seq`, `tz_offset_min`, `surface`.
