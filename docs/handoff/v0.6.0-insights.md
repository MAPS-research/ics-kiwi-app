## Deviations

- **D1 (TDD order).** I wrote the server modules first and the tests in the same pass, so the tests did not run red before the implementation existed. Several were red→green during the work: the trend window, the `no_activity` tenure rule, and quantile rounding. They also caught two cross-workstream changes (see D9).
- **D2 (explorer dual mode).** `GET /api/teacher/analytics/table` serves the v0.6 explorer when the request has `v=2`, any v0.6-only parameter (`from, to, where, work, origin, groupId, questionType, difficulty, policyVersionId, includeStaff, tag, fold, columns`), or a v0.6-only group (`chapters, reading, question-activities, study-sessions`). Otherwise it serves the unchanged v0.5.1 shape for cached bundles and the moved tests. Legacy group names map to the v0.6 groups inside v2 requests.
- **D3 (aggregation source).** All v0.6 metrics aggregate `events` with their derived columns, and the population is decided at query time. They do not use session counters, even for the whole term (§13.4 said session counters). This keeps INSIGHTS independent of TELEMETRY's `sessions-v3` rebuild. Benchmark: 114–230 ms for a whole term over 50k events.
- **D4 (AI tutor questions).** This counts `ai_question` events plus legacy `hint_requested`. A Lab turn is counted once because the server writes one `ai_question` event per `chat_turns` row; native Kiwi turns are included. Client copies of server-owned events (`payload._clientReported`, set by TELEMETRY) are excluded from attempts and AI counts (P2). Only the Research `Client-reported accuracy` column reads them.
- **D5 (attention details).**
  - `no_activity` measures time on the roster from the earlier of `roster.created_at` and the first recorded event.
  - `low_accuracy` counts every server-checked attempt in the current chapter (teacher questions and AI items).
  - `missing_work` names the assignment title (`Missing Week 2 HW`).
  - Under the Students group, the Activity filter is the one filter that drops zero-activity students; every other filter keeps them.
- **D6 (trend window).** On Course metrics, the cards use the selected range. The weekly trend chart covers the term up to the end of the range, because a "since last class" window would be a single bar.
- **D7 (outages).** `analytics.outages()` implements the §13.10 merge locally to shade trend buckets. TELEMETRY owns Data health; INTEGRATION may swap in TELEMETRY's function.
- **D8 (Flagged replies).** `needsAction.flaggedReplies` is `null` until any `chat_turns` row of the class has a guard status other than `not_applicable` or a flag. This is a data-driven reading of "hidden until AIRUN ships the guard".
- **D9 (moved test edits, `server/test_insights.py`).** Two edits to the first moved case, both caused by TELEMETRY's ingestion changes:
  - Its two `answer_submitted` events are now written by the server. A client copy no longer counts as an attempt.
  - It registers roster names (`Ada`, `Bo`). Event names now come from the roster.
- **D10 (thread keys).** Keys longer than the router's 120-character parameter limit keep a 108-character prefix plus `~<sha1[:10]>`. PEOPLE's export filter compares full keys, so "This thread (CSV)" would miss such a thread. This only happens for thread ids longer than about 75 characters.
- **D11 (native feedback).** Feedback with index k attaches to the k-th `ai_responses` row of the conversation, ordered by time. Without `ai_responses` rows it attaches to the k-th native turn. This is approximate, as §15.2 says.
- **D12 (timeline grades).** Grade steps come from `grade_events`: `save_draft` reads "Draft n/m", `release`/`bulk_release` "Released n/m", `unrelease` "Grade unreleased". `grade_released` events are skipped so a release is not shown twice. `autocheck` rows are skipped.
- **D13 (range parameters).** Home and every Insights endpoint also accept `preset=` and compute the range on the server. The pages send `from/to/compareFrom/compareTo` as INSIGHTS-10 says. With no parameters the range is the whole term (§6.0).
- **D14 (one-student exports).** The timeline, question activity, and explorer views filtered to one student ask for a purpose of at least 5 characters before Export ▾ appears, because PEOPLE's export rejects a one-student export without one.
- **D15 (Home links for viewers).** Missing › List goes to the assignment list for roles with `viewAssignments` and to Students needing attention otherwise. Assignment rows go to grading for `grade` roles and to the explorer's question activities otherwise.
- **D16 (fixture dates).** The spec's example "Due Fri 10/24" falls on a Saturday in 2026, so the tests use `Sat 10/24 23:59`.
- **D17 (re-teach line).** It reads `1. HW3 Q2 left_join() 38% first try · 2.9 tries · 9 students`. That is the spec format plus the basis ("first try") and the number of students.
