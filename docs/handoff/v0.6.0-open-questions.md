## A. For the Kiwi maintainers

### A1. Identity boundary (spec §14.6) [AU-D4-11, AU-D3-26]

`.local/kiwi/CLAUDE.md` says that apps never receive identity. The local CSS Lab bridge (`scripts/local-kiwi/bridge/lab-bridge.controller.ts`) still returns student emails and the class roster to the Lab, as in v0.5.

v0.6.0 keeps that trust model, because teachers rely on readable names for grading. On top of it, v0.6.0 adds:

- app-local display names and `showEmails=false`;
- Presentation mode;
- HMAC research ids;
- consent filtering;
- an access audit;
- `consent` in the bridge projection;
- a researcher role that never sees identities (D3).

Please forward these questions:

1. May the CSS Lab bridge, a first-party controller installed locally, return student emails and the class roster to the Lab? Or must it return opaque UUIDs only, with names resolved by the instructor inside Kiwi or by a roster the teacher imports?
2. May the bridge return `User.consent` per student? Or should Kiwi itself filter non-consenting students' activity for research exports, as `app-context.service.ts:39-44` does?
3. Can Kiwi provide a class-bound service credential with analytics scope? It would let the Lab sync native activity on a schedule without a teacher session and receive tombstones for deletions. Deferred, see B.
4. Should a grade-passback endpoint exist (Lab → Kiwi gradebook), or is CSV import the intended path? Today the Lab offers Grades for LMS CSV and the Student × assignment status CSV.
5. Confirmation only: the owner ruled (D1) that InstructorClass `assistant` (`userRole: 'ta'`) maps to a Lab TA who can grade. Please say so if Kiwi's assistant role is not meant to include grading.

Fallback if the answer to 1 is "UUIDs only" (already implemented):

- set Course settings › Privacy › `showEmails=false`;
- import display names by student id;
- remove `email` from the bridge projection (a one-line change, spec §15 item 4).

### A2. Upstream proposals for the two local host patches (D5)

The local demo patches `.local/kiwi-ui` through the idempotent mechanism in `scripts/local-kiwi/frontend.mjs`, which is re-applied on `demo:start`. The bridge UI tests are run by `npm run test:bridge`. A production Kiwi should not depend on local patching. Please consider adopting these two changes, or an equivalent official API.

1. **Per-page chat availability for embedded apps** (patch 1: `ClassAppView.tsx`, `GlobalChatContext.tsx`; test `hides chat while unavailable`).
   - Message: the app sends `kiwi:setChatAvailability {available: boolean, reason?: string}`.
   - Effect: while the sending app page is shown, `available: false` closes Kiwi's global side-panel chat and hides its open button. `available: true`, or leaving the page, restores the chat.
   - Lab use: the Lab sends it for homework whose Student help turns Ask Kiwi Off.
   - Further request: an official per-page `tutoringMode` (this was Kiwi question 5).
   - Without either: Kiwi's own chat stays available in guidance mode and does not know the assignment's answers. The assignment editor says so.
2. **Return to the requested page after sign-in** (patch 2: `ProtectedRoute`, `Login`; test `returns to the requested path after login`).
   - Redirect: `ProtectedRoute` sends a signed-out user to `/login?returnTo=<path+search>`.
   - After sign-in: `Login` navigates to `returnTo`, but only when it is a same-origin path (starts with `/`, not `//` or `/\`), so the parameter cannot become an open redirect.
   - Without it: the global CSS Lab teacher link lands on Kiwi's home page after sign-in instead of the Lab teacher entry.

## B. Deferred past v0.6.0 (spec §20)

Each item has a concrete blocker, and v0.6.0 ships a replacement. Spec §20 has the full table.

- **Scheduled native sync and Kiwi-side deletions.** These need a Kiwi service credential and a change feed (A1 question 3). v0.6.0 runs one sync loop per teacher session and keeps Lab-side tombstones.
- **Retrieval over Kiwi-hosted lecture materials (RAG).** This needs a host-mediated retrieval endpoint. v0.6.0 uses teacher-provided chapter files as AI reference (≤ 8,000 characters).
- **Composable assignment modes** (`countsToGrade`, `completionCredit`). These need a teacher decision on how completion credit maps to points.
- **Merging a revision with its original.** This needs per-question reconciliation rules. v0.6.0 stores `revision_of` and `question_id_map`.
- **Encrypted storage of the id → name/email mapping.** The Python standard library has no authenticated encryption.
- **Questions parsed from `.qmd` and a cross-course bank.** The course's `.qmd` files have no stable question-block format.
- **IRT difficulty calibration.** It needs far more responses per item than a pilot produces.
- **Course announcements.** Kiwi already provides them.
- **Grade passback.** This needs a Kiwi endpoint (A1 question 4).
- **Server-side R execution.** This is excluded by design: R runs only in the browser through webR.
- **An official Kiwi SDK chat-availability API.** See A2.
- **Production deployment.** v0.6.0 is a local pilot.

## D. Behavior choices that ship as documented (no ruling requested)

The workstreams chose these behaviors where the spec left a detail open. They ship as described here and in the handoffs. Change one only if you ask.

- **Assessments.**
  - Timed homework at 0:00 auto-submits the current answers, and blank answers are stored as `""` (ASSESS 2).
  - Rubric and tags stay editable after the first attempt (ASSESS 1).
  - `Reopen` only clears `close_at` (ASSESS 3).
  - Students see due dates in their browser's time zone (ASSESS 4).
- **Grading.**
  - `counts.graded` includes drafts.
  - The default bulk release also releases drafts on older attempts.
  - `grades.csv` ignores Presentation mode, because an LMS import needs names.
  - A TA with `taCanRelease` can release grades but not unrelease them (GRADE 1–4).
- **Standalone access.**
  - With `KIWI_TEACHER_KEY` unset, staff keys fail closed too (503).
  - Built-in demo sessions last 7 days.
  - Migration backups go to `<db dir>/backups/` (FOUNDATION 1, 2, 4).
- **AI tutor rules.**
  - "Test this rule" builds its own context, using the same `ai_runtime.assemble` and context keys as the student paths (AIRULES 1).
  - Teacher-test items are not stored in `generated_items` (AIRULES 3).
  - Real test runs use the per-minute budget of `preview-<staffUserId>` (AIRULES 4).
  - The free-practice scope saves with "Save chapters" (AIRULES 5).
- **AI runtime.**
  - Only predict items are verified (AIRUN 1).
  - When the rewrite also leaks, the original reply is redacted, as §12.5 says literally (AIRUN 2).
  - The Ask-Kiwi-off refusal is logged as `blocked_tool_policy` but not counted as "AI request turned away" (AIRUN 3).
  - The daily item limit also counts similar practice (AIRUN 4).
- **Telemetry and Insights.**
  - Keepalive flushes may resend events; the server deduplicates them (TELEMETRY 5).
  - The Course metrics trend runs term-to-date up to the end of the range (INSIGHTS 1).
  - Zero-activity students are dropped only by an Activity filter (INSIGHTS 2).
  - The Flagged replies chip appears once any guard status exists (INSIGHTS 3).
  - Thread keys over 120 characters are shortened for the router (INSIGHTS 4).
- **People.**
  - Earlier `teacher_actions` rows keep the raw student id after anonymization (PEOPLE 2).
  - The export group filter uses current membership (PEOPLE 3).
  - Retention leaves `learning_sessions` under the real id (PEOPLE 4).
- **Short assignment labels** (found by INTEGRATION). `HW3 Q2`-style labels took the first number in the title, so "Review-v0.6 HW" read `HW0`. **Resolved** (browser review RV6-M04): a number counts only after a sequence word, other titles are shortened, and labels are unique per course.
