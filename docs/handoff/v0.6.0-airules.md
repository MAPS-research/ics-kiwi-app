## Deviations

- **D1 Additive response fields** (frozen §7.6 shapes are a subset): overview cells carry `inheritsFrom` and the overview has `courseCells` (course × group); `POST /api/teacher/ai/test` adds `status` (the `ai_calls` status of a real run), `error` (invalid item) and `policyLabel`; `/rules/homework-questions` and `/chapters/summary` are new. Local TS types live in `policyForm.ts` (CR-AIRULES-2 moves them to `src/types.ts`).
- **D2 Two convenience endpoints** (STAFF_VIEW / `viewAiRules`, §5.1 "chapters convenience endpoints"): `GET /api/teacher/chapters/summary` (per chapter: assignments, lecture materials, AI-rule cell, `referenced`, chapter files) and `GET /api/teacher/ai/rules/homework-questions?unitId=` (prompts only, no answers; `protected`, `askKiwi`). The UI calls them with the exported `request()` from `api.ts` (CR-AIRULES-1 adds typed methods).
- **D3 `restoredFrom`** stores the source **version id** (`policy_versions.id`), not its version number; the UI resolves it to `Restored from vN`.
- **D4 `created_by`** of new versions (and of saved checks) is the actor label (`Instructor (local key)`, staff display name, or the Kiwi caller's username) so history and overview can show who saved without another lookup; the legacy PUT does the same.
- **D5 Legacy `PUT /api/teacher/policies`** no longer rejects CJK (§12.1 removes the rejection); FOUNDATION had kept it on the legacy form.
- **D6 Teacher-test items are not persisted** in `generated_items` (no student-facing records); the item comes back as a synthetic `GeneratedItemTeacher` with id `test-<aiCallId>`. Only the `ai_calls` row is written.
- **D7 Test protection**: in a teacher test the chosen homework question is always protected (even when `answer_protected` is false for the teacher's pseudo-student `preview-<userId>`), so the guard can be tested on any homework question. Matching still uses `readers.open_homework_questions`.
- **D8 Test context**: built by AIRULES with the baseline `assemble` context keys (`chapter, goal, packages, datasets, materials, helpLevel, assignmentKind, question, starterCode, instructions, code, error, type, difficulty, focusNote, prompt`). If AIRUN's real chat/generation path builds context differently (key names, history, recent exercises), the dry run and the live request can drift — see Open question 1.
- **D9 Free practice scope** is part of the Chapters draft and saved with `Save chapters`; only `This week's chapter` saves on select (spec text only requires that for the dropdown). Saving this week's chapter keeps unsaved card edits (`mergeThisWeek`) and refreshes `updatedAt`, so the next `Save chapters` does not hit 409.
- **D10 No AIRULES migration.** An index on `ai_test_samples(class_id, unit_id, group_id, created_at)` was tried and reverted: frozen `test_core.test_init_db_twice_on_fresh_db` / `test_init_db_twice_on_snapshots` assert `applied_versions == core MIGRATIONS` exactly, so **any** workstream migration fails them (CR-AIRULES-3).
- **D11** The `Chapter` and `Applies to` pickers stay enabled for TAs/viewers (they only navigate between read-only scopes); every rule control is disabled.
- **D12 `usedToday`** = free + similar items (status not `rejected_*`) generated for the student since local midnight in the course time zone, across chapters. AIRUN enforces `dailyItemLimit`; the two counts must agree (Open question 2).
- **D13 `GET /api/policy`**: an unknown chapter → 400 `invalid_request`, a hidden chapter → 404 for students and previewers (staff still see it); v0.5.1 returned defaults for any id.
- **D14 Saved-check expectations**: `guard: "clean"` passes on `clean` or `not_applicable` (no protected question); `leak_handled` passes on `retried_clean|redacted|blocked` or a `blocked_tool_policy` refusal. A run is capped at 20 checks; checks that cannot be assembled (e.g. a deleted homework question) report `passed: false` with the reason instead of failing the whole run.
- **D15** Restoring without a note stores an empty note (the source is in `restored_from`; the history shows `Restored from vN`). Every checkbox on the AIRULES pages has an explicit `aria-label` (also when wrapped in a `<label>`), for the INTEGRATION-02 static scan.

## Open questions

1. **Shared context builder.** Should AIRUN expose one `ai_runtime` function that builds the request context (chat and generation) so "Test this rule" assembles exactly what students get? Today AIRULES builds the test context itself (D8).
2. **Daily quota count.** Is `PublicPolicy.practice.usedToday` (D12: free + similar, non-rejected, since local midnight, all chapters) the same count AIRUN uses to enforce `dailyItemLimit`? If not, one of us should change.
3. **Persist teacher-test items?** `generated_items.origin` allows `teacher_test`. D6 keeps them out; if research wants every generated item, they could be stored with `is_preview=1`.
4. **Rate budget of real test runs.** Real tests and saved-check runs go through `ai.invoke` as `preview-<staffUserId>`, so they use that pseudo-student's per-minute budget (and count toward the class budget once AIRUN's `RateBudget` lands). A 20-check run can therefore hit `rate_limited`; each such check reports `AI request failed: …`.
5. **Free practice scope on select?** Teachers may expect it to save immediately like `This week's chapter` (D9).
6. **Browser review (§19.3 B8/B9)** with a configured AI key is still open: real `Run test`, real saved-check runs and the guard rewriting a live reply were only tested with a faked provider.
