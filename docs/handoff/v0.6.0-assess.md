## Deviations

1. **Timed auto-submit** — `POST /api/work/{id}/submit` accepts `autoSubmit: true` only for timed homework with a started attempt; blank answers are then stored as `""` instead of 400 `incomplete_submission` (the spec has the client auto-submit "the current answers" at 0:00). Extra ids are still refused. Test `test_timed_auto_submit_accepts_blank_answers`.
2. **Rubric and tags stay editable after attempts** — the freeze compares every question field except `graderRubric` and `tags` (staff-only, do not change attempts or grades). The editor locks everything else and keeps those two fields enabled.
3. **Hints are revealed, not shipped** — `StudentAssignment.questions[].hints` holds only the hints already revealed to that student (one per wrong in-class attempt); `InClassCheckResult.nextHint` adds the next one. Sending all hints up front would defeat "one at a time".
4. **Delete** — attempts → 409 `has_submissions` (as specified); a published assignment without attempts → 400 "Unpublish this assignment before deleting it, or archive it" (the spec only allows drafts and names no code for this case).
5. **Attempt start status** — 201 when a start is created, 200 when the open start is returned again (same body).
6. **In-class checks and the late policy** — checks are blocked only by `open_at` (409 `not_open_yet`) and `close_at` (409 `assignment_closed`); a due date with `not_accepted` does not block in-class checks.
7. **Complete-code without a run** — returns `correct:null` (`not_gradable`, "Run your code…") unless the answer equals the reference code; v0.5.1 compared the code text with the expected value. Homework autocheck of complete questions without a run is therefore "Needs review" for GRADE.
8. **Judging details** — R index prefixes (`[1] `) are ignored on both sides; quotes are no longer stripped (v0.5.1 did); `exact` whitespace mode trims only the ends; numeric tolerance defaults to 1e-9 relative whenever both sides parse as numbers (stored explicitly per question when the reference is numeric).
9. **Student `GET /api/submissions`** returns the v0.5.1 keys plus `StudentSubmission` keys; `grade`, `feedback`, `gradedAt` and `items` are null until `grade_status='released'` (B2 marks pre-0.6 graded rows released, so the moved grading test still sees its grade).
10. **Submit events** use session id `submission-<id>` (as `testsupport.make_autochecked_submission` does) rather than the client `sessionId`; payloads add `unitId`. New submissions in Kiwi-linked classes store `student_name = ''` (§4.2.1 note).
11. **Starter assignments** — the legacy `POST /api/teacher/samples` now uses the same starter logic: dedupe by `starter_key` and by v0.5.1 titles (`legacyTitles`), and skip samples whose chapter is missing (v0.5.1 created them). The in-class sample is titled "In-class exercise · R basics and data wrangling" (was "Class practice · …"); samples carry v2 fields (`studentExplanation`, `graderRubric`, `referenceCode`, `expectedOutput`, hints).
12. **Legacy attachment delete** (`DELETE /api/teacher/files/legacy-<id>`) keeps the blob as a soft-deleted `course_files` row before clearing `assignments.file_*`.
13. **Additive response fields** — `GET /api/teacher/assignments` rows add `hasPreviewRows` (drives "Clear test submissions"); `StudentAssignment` also carries `classId`, `status`, `openAt`, `createdAt`, `updatedAt` (v0.5.1 `Assignment` keys for cached bundles); staff `Submission` rows add `gradeStatus`, `isLate`, `lateSeconds`, `isPreview`, `overTime`, `timeUsedSeconds` (optional in §7.4). `GET /api/files/{fileId}` and `GET /api/work/{id}/files/{fileId}` also admit STAFF_VIEW (editor downloads).
14. **Student dates** are formatted in the browser time zone ("Due Sat 10/24, 3:59 PM"): `GET /api/teacher/settings` (course timezone) is staff-only. Teacher pages use the course timezone when PEOPLE's settings endpoint answers, else the browser zone.
15. **Popover "Last active"** is the student's last non-preview event in the course (not only on this assignment).
16. **Draft local fallback** — the v0.5.1 `kiwi-work-<class>-<student>-<id>` localStorage key is kept and upgraded to `{v:2, answers:{qid:{value,ts}}}`; per question the newer of server/local wins and unsynced local values are re-sent.

## Open questions

1. Deviation 2: should rubric/tag edits after the first attempt stay allowed (useful for TAs while grading), or follow the spec's fully read-only Questions section?
2. Deviation 1: is auto-submitting blank answers at 0:00 acceptable, or should timed homework keep requiring complete answers (then the client cannot auto-submit an unfinished attempt)?
3. `Reopen` only clears `close_at`. When the due date has passed and late work is "Not accepted", the assignment stays closed until the teacher changes the late policy. Should Reopen also switch the late policy to "Accepted, marked late"?
4. Course timezone for students: should `GET /api/course` expose `schedule.timezone` so student due dates use the course zone (§9.1 shows "Due Fri 10/24 23:59 Asia/Shanghai" on the teacher side only)?
