### Server

- **`server/leak_guard.py`** implements §12.5 completely:
  - Normal forms `N`, `L` and `CW` keep an index map to the original text. Tokens and 3-shingles are built from them.
  - Homework matching uses containment, with the short-prompt substring rule and these tie-breaks: same unit first, then latest due date. `protection()` / `protected_for()` combine the explicit question, the homework match and the source of a similar item.
  - Reply rules: R1, R1′ (novel part), R2 (line coverage), R3 (numeric value, keyword/arrow/CJK context, R output lines, rounding), R4 (choice assertion and letter), R5 (short token).
  - Item mode: code rules plus CW equality of the item's answer, expected output and choices.
  - `redact()` merges overlapping spans in the original text and prepends the notice.
  - Also exports `RETRY_INSTRUCTION`, `BLOCKED_REPLY` and `jaccard()`.
- **`server/ai.py`**:
  - `invoke()` makes exactly one provider call and raises `AiError` for every failure: timeout and network errors → 502 with `details.reason`, provider 429 → 429, incomplete reply, invalid or empty output. It fills `meta` with usage data.
  - `Capacity` (`_slots`): `KIWI_AI_CONCURRENCY` slots, a wait of up to `KIWI_AI_QUEUE_WAIT_S`, and at most 32 waiters before answering `busy`.
  - `RateBudget` (`_rates`): atomic multi-key reservation and `refund()`. Rejected reservations record nothing.
  - `ai.init(db)` runs the startup hygiene.
- **`server/ai_runtime.py`**:
  - `assemble` / `assemble_with_meta` follow the §12.2 order. They load chapter packages, dataset columns and AI-reference material (cut at 8,000 characters with `[… truncated]`; the original length goes to `context_json.truncated.materials`). Context fields are cut per `contextFields`, and history is limited to `historyTurns` of the same thread and question/item.
  - Two-phase logging: `log_call` commits a `pending` row; `invoke()` asserts that no transaction is open; `finish_call` writes the result. Helpers: `failed()` / `reject()` (final row plus an `ai_request_failed` event) and `reserve_budget` (per student, per class, and per address for standalone classes).
  - `provider_slot()` and the test hook `current_db()`. `call_provider()` lets other workstreams make slot-limited calls.
  - `init()` / `ensure_init()` turn `pending` rows older than 10 minutes into `interrupted`.
  - `policy_label()`.
  - The full **chat pipeline**:
    1. Resolve the policy, then the assignment's tool policy (`tool_disabled`), then chapter access (`chapter_closed`, `aiTutorEnabled`).
    2. Run homework matching on every request. A match whose homework has Ask Kiwi off gets the fixed refusal with no provider call.
    3. Check the budget, then use local guidance when there is no key, otherwise call the provider.
    4. Guard the reply: one rewrite, then redaction of the original reply. The `chat_turns` row is flagged with `flag_source='guard'`.
    5. Write the server `ai_question` event with `chatTurnId`, `aiCallId`, `policyVersionId` and `effectiveAccess`.
  - Also `chat_history`, `set_turn_flag` (staff flag/unflag; audited; keeps `guard_status`) and `call_detail` (`AiCallDetail` plus its retry rows).
  - `validate_question` now accepts `explain` items (with a `rubric`), `choiceCount`, and non-English text when the reply language is not English. `is_novel` now covers numeric, character and logical vectors, `data.frame`/`tibble` literals, and 3-gram Jaccard ≥ 0.8 against the student's last 5 items.
- **`server/generated_items.py`** (§12.8):
  - Free-practice and similar-practice pipelines:
    1. Access, policy and type/difficulty checks.
    2. `allowFocusNote`, the unlock rule (`difficulty_locked`) and the daily quota.
    3. Homework matching on the focus note: `blocked_homework_match`, or the item becomes homework-derived.
    4. Budget, then the provider, or local templates and the teacher bank.

    9. The student receives `GeneratedItemPublic` without any answer key.
  - Server checks (`answer_submitted` with `checked_by='server'`, `attemptIndex`, `timeOnItemMs`, `basis`; replays of the same `eventId` are not counted twice). Explanations are withheld for homework-derived and similar items while the homework is protected.

## Deviations

1. **Token-like forms use R5, not R1.** A protected form that is a single token or shorter than 6 characters is judged by R3/R5 (whole token with context), not by the R1/R1′/R2 substring rules. §12.5 lists `social` (6 characters) as an R5 example; without this change "Think about social data" would be flagged by R1.
2. **A sentence-final period no longer hides a number.** The number regex's lookahead is `(?!\w|\.\w)` instead of `(?![\w.])`, so "It returns 4." is caught; "4.5" is still one number. `re.ASCII` is used so CJK neighbours ("答案是5") do not hide numbers.
3. **Verification applies to predict items only.** For complete-code items the reference solution is staff-only, so the browser has nothing to run. Their checks already use the student's run output (`basis='client_run_output'`), and `verification` stays `not_applicable`.
4. **Legacy request shape.** A chat or question body **without** `surface` (v0.5.1 clients, `test_core.test_ai_errors_map_to_status_codes`, the KEEP novelty test) always goes to the provider, so without a key it still answers 503 `ai_unavailable`. v0.6 bodies (with `surface`) get local guidance or local templates without a key, as §6.6 specifies. `chat_turns.surface` is `legacy` for such bodies.
5. **Leak and novelty retries are child `ai_calls` rows** (`attempt=2`, `parent_call_id`). The parent keeps the original reply in `raw_output` and the final status (`leak_retried_clean`, `leak_redacted`). Request counts must use `parent_call_id IS NULL` (the capacity test does). Redaction is applied to the original (first) reply, as §12.5 says.
6. **`aiTutorEnabled=false`** blocks chat outside assignments (403 `tool_disabled`). Inside a visible assignment its tool policy governs.
7. **Similar items are always guarded against their source question**, in-class exercises included. Explanations are withheld only while `answer_protected` holds.
8. A focus note sent while `allowFocusNote=false` answers 400; it is not dropped silently. The daily limit counts free and similar items per course-timezone day.
9. **Statuses.**

   | Outcome | `ai_calls.status` | Notes |
   |---|---|---|
   | Generation rejected for a leak twice | `validation_error` | `guard_status='blocked'`, HTTP 422 `unsafe_item` |
   | Unparseable JSON | `invalid_output` | |
   | Schema failure | `validation_error` | |
   | `no_local_practice` | `unavailable` | |
   | Provider HTTP 429 | `rate_limited` | |
   | Ask-Kiwi-off refusal | — | stored as a `chat_turns` row with `source='local'` and `guard_status='blocked'` |

10. **Additive API.**
    - `GET /api/practice/status?unitId` (STUDENT): `{usedToday, dailyItemLimit, unlockAfterCorrect, startingDifficulty, unlockedMaxDifficulty, effectiveAccess, policyLabel}`.
    - Extra response fields: `ChatResponse.helpLevel`, `ItemCheckResult.feedback` / `verificationNotice` / `withheldMessage`, extra `GeneratedItemTeacher` and `AiCallDetail` fields (see CR-AIRUN-2).
    - The client calls the new route through the exported `request()`; `checkItem` sends `timeOnItemMs` the same way.
11. **Startup hygiene runs lazily.** `ai_runtime.ensure_init` runs at most every 5 minutes, on the first AI request of a process (see CR-AIRUN-1).
12. **The client no longer posts** `ai_question`, `question_generated`, `similar_requested` or item `answer_submitted`; the server writes them. The student UI drops the eyebrow and accent-dot headings on AIRUN's student pages.

## Open questions

1. Should complete-code items also be verified, for example by giving the client a hidden verification run of the reference code? That would expose the key to anyone inspecting traffic, which is why v0.6 verifies predict items only.
2. Redaction uses the original (first) reply when the rewrite also leaks (§12.5 literal). Should it use the rewrite instead, which was asked to be hints-only?
3. Should the Ask-Kiwi-off refusal count as an "AI request turned away" on Home? It is logged as `blocked_tool_policy`, with no `ai_request_failed` event because the student gets a reply.
4. Should the daily item limit apply to similar practice inside assignments? It currently does.
