## Deviations

1. **Partial saves stay "Needs grading".**
   - `action: "save"` stores whatever item scores and comments are given, but `grade_status` becomes `draft` only when every question has a score. Until then it stays `ungraded`, `grade` stays NULL, and the card says "score every question to save a draft".
   - `action: "release"` (and release generally) needs every question scored; otherwise it returns 400 `invalid_request` with `details.missing`.
   - Questions left out of the body keep their stored score, or the auto pre-fill, and their comment. This is what "Apply score to group" relies on.
2. **`grade` holds the total of draft and released grades**, as in §4.2.1. Students are protected by ASSESS's masked `GET /api/submissions`. `released_at` is set only while the grade is released.
3. **Counts** (`grading_rules.grading_counts`) are over the latest attempt per student and assignment, within the population:
   - `graded` = draft + released (the baseline counted released only; `test_core` stays green);
   - `draft` = `toRelease` = latest drafts.
4. **Default bulk release scope.** It releases every non-preview draft of the assignment, older attempts included. Preview drafts are released only when listed in `submissionIds`.
5. **Students outside an assignment's audience** with no submission get state `not_submitted` with the label `Not assigned`. The frozen state type is unchanged. The status CSV skips them.
6. **Cell rules.**
   - `Missing` uses due date + grace minutes.
   - `newer_ungraded` uses released earlier attempts only.
   - `highest` takes the best released attempt; a latest-attempt draft shows as `draft`.
7. **Integrity flags.**
   - AI-reply and paste evidence counts only up to `submitted_at`.
   - `paste_from_ai` matches `events.attribution_assignment_id` or `payload.assignmentId`.
   - `identical_answer` normalizes answers (trim, collapse whitespace, casefold), needs at least 40 characters, and compares with other students' latest submissions in the population. Its text names the largest group: `Same answer as <n> other student(s)`.
8. **Adjustment changes** write an extra `grade_events(action='adjust')` row before the save or release row. Its `items_before_json`/`items_after_json` hold `{points, reason}`.
9. **Released gradebook cells read `Released 18/20 · 1 submission`.** The UI prefixes `Released ` to the frozen server label (`grading_rules.cell_label` keeps `18/20 · 1 submission`, as asserted by `test_core`). This satisfies GRADE-11 and NM18 together.
10. **Extra audit and events.**
    - `GET /api/teacher/submissions/{id}` is declared `audit="gradebook"`. The spec lists no audit for it, but it shows student work.
    - Mutations are audited as `grade_save`, `grade_release`, `grades_release`, `grade_unrelease` and `grade_legacy`.
    - The legacy `POST /api/submissions/{id}/grade` now also writes a `grade_released` event, because it releases.
11. **Legacy hub** (`GET /api/teacher/hub`): same v0.5.1 shape; preview rows are now excluded.
12. **Exercise results.**
    - A missing `from`/`to` means the whole term (§6.0). The page itself requests the `this_class` preset range by default.
    - Correctness comes from `checked_by='server'` rows; `legacy_server` rows count only through `rejudged_correct`.
    - Text answers count as attempted but not in the percentages, which are rounded integers.
    - The gradebook in-class columns use completion = distinct questions checked ÷ questions and accuracy = correct ÷ gradable checks (§13.9).
13. **grades.csv.**
    - `releasedOnly` defaults to 1.
    - The `Late` and long-layout `late`/`over_time` columns are `yes`/`no`.
    - Email is filled only when `privacy.showEmails` allows it.
    - Rows are sorted by student label.
    - `X-Name-Mode: pseudonyms` does not pseudonymize this LMS file, because an LMS needs names (open question 3).
14. **UI decisions.**
    - The gradebook Export ▾ is a native `<details>` disclosure. The frozen `ExportMenu` handles downloads only; here Activity log, AI conversations and Research package link to the Exports page.
    - Card dates use the browser time zone; course settings belong to PEOPLE's endpoint.
    - The To grade pickers use the legacy staff routes `GET /api/work-options` and `GET /api/work/{id}` (through `api.workDetailLegacy`).
15. **FOUNDATION baseline exports removed.** `legacyGradingStatus`, `hubCsvRows` and the HubData `GradebookView` are gone; nothing else imported them. `GradingCardView` moved to `GradingCard.tsx` with new props.

## Open questions

1. Should `counts.graded` include drafts (current behavior) or only released grades? INSIGHTS' Home uses `toGrade` and `toRelease`, which do not change either way.
2. Default bulk release: should it release drafts on older attempts too (current behavior), or only latest attempts (what `toRelease` counts)?
3. Should `grades.csv` honor Presentation mode (`X-Name-Mode: pseudonyms`)? Currently it does not, because LMS imports need names; the status CSV has its own `pseudonymize=1`.
4. `unrelease` is INSTRUCTOR-only per §6.4, so a TA with `taCanRelease` can release but cannot unrelease. Confirm.
5. `grade_released` events are written with the student's identity, labelled through `identity.label` as `testsupport.student_identity` does. TELEMETRY's final `add_event` decides `student_name` for linked classes.
