# v0.6.0 decisions on the open product questions

Date: 2026-10-22. The user asked for the spec's open questions to be resolved and for frontend coverage tooling to be installed. These rulings are binding for the remaining v0.6.0 work and override the spec where they differ. Each ruling records the reason so it can be revisited.

## D1. Kiwi assistants become Lab TAs (confirmed)

- **Ruling:** keep the spec default (§5.3 step 1b). A Kiwi assistant (`userRole == 'ta'`) with analytics or materials permission is a Lab **TA**: can grade and view Insights, cannot edit assignments' questions or AI tutor rules. Instructors can override any Kiwi staff member's Lab role on Course settings › Staff & roles.
- **Why:** grading is the TA's core job, while AI tutor rules and assignment design are instructional (and, in studies, experimental) controls. Restricting edits to instructors keeps conditions consistent across sections; the per-person override covers co-teaching assistants.

## D2. Homework answer protection ends when the homework closes by default

- **Ruling:**
  - New homework defaults to `Solutions visible: After the due date` (`solutions_visibility = 'after_due'`) instead of `Never`. With the existing `readers.answer_protected` rules this means: protected while students can still submit (open, or past due with late submissions accepted); **not protected once the assignment is closed** (no more submissions possible), so Ask Kiwi may then discuss the answer and the student sees solutions.
  - `Never` stays available for assessments the teacher will reuse (e.g., next term). It keeps answers protected until the teacher archives the assignment or changes the setting.
  - Existing (migrated v0.5) homework keeps whatever value the migration assigned; nothing changes silently.
  - The editor's Student help note and the assignment list show the **actual** protection state instead of a fixed sentence, e.g. `Ask Kiwi won't give final answers until this homework closes (Fri 10/24 23:59 + late window to Sun 10/26 23:59).`, `… until you archive it or make solutions visible (Solutions visible: Never).`, or `Answers are no longer protected: this homework is closed.` When the homework has no hard close (late submissions accepted with no end date), say so: `… there is no closing date, so answers stay protected until you set one or archive the homework.`
- **Why:** after the assessment window, worked solutions and AI explanations are valuable for learning; protecting forever by default surprised teachers. Teachers who reuse items choose `Never` deliberately, and the UI makes the consequence visible.
- **Addendum (2026-10-22, second review, TEACHER-03):** with the spec's default late policy (`Accepted, marked late`, no end date) a new homework never closed, so the D2 default never took effect. The editor now gives **new homework a 7-day late window**: once a due date is set, late work is accepted (marked late) until 7 days after it, and the window follows the due date until the teacher edits the late policy. The homework then closes, solutions appear and Ask Kiwi may discuss the answer. `Accepted, marked late` (no end) stays available and the editor says that the homework then never closes. The server's default for API and legacy (v0.5) bodies is unchanged (`accept_marked`), existing homework keeps its policy, and a close date earlier than the due date is refused. Homework with a close date and no due date shows solutions once it closes (CORRECTNESS-08).

## D3. New staff role: `researcher`

- **Ruling:** add a fourth staff role `researcher` (alongside `instructor`, `ta`, `viewer`):
  - **Can:** open Insights (Activity explorer, question activities, answers by question, timelines, AI conversations incl. Coding mode and coded-conversation export, Course metrics, Data health), read Chapters & AI tutor rules and Groups **read-only** (to know conditions and policy versions), and export the research package and activity/AI-conversation/generated-item exports.
  - **Never sees identities:** the server forces pseudonymous names for every researcher response (as in Presentation mode, regardless of the client's name mode) and, for every export, forces `pseudonymize=1`, `consent=yes`, `allowUnverified=0`, and refuses per-student case files (`student/{id}.zip`). Free-text fields are scrubbed of roster emails/names the same way Presentation mode does.
  - **Cannot:** grade, release grades, edit assignments, AI tutor rules, chapters, roster, groups, privacy, staff; cannot use Preview as student; cannot see Home's named action lists (Home shows the anonymized metrics view or redirects to Insights).
  - **How assigned:** standalone courses via a staff key with role `researcher`; Kiwi-linked courses via Staff & roles override on a Kiwi course staff member (Kiwi stays the authority on who is staff; no automatic Kiwi role maps to researcher).
  - `viewer` stays as a read-only observer (e.g., a co-instructor) with the spec's export restrictions.
  - Every researcher data access is written to `data_access_log` with the role.
  - **Addendum (2026-10-22, second review):** the consent and identity rules apply to the JSON views too, not only to exports. Researcher requests are restricted to consenting students at query time (every population query, list rows and single records; a request aimed at a non-consenting student answers 404), and every student id in a researcher response is replaced with the student's research id (the same `P…` id as in research exports; incoming research ids are translated back). Free-text scrubbing now covers the whole roster in de-identified exports (a consenting student's text that names a classmate), and Presentation mode scrubs free text for every staff role (SECURITY-01/02/04/05, CORRECTNESS-03).
- **Implementation note:** v0.6.0 has not been deployed to any live database yet, so the `staff.role` CHECK constraint in the 0.6.0 DDL is edited directly to `('instructor','ta','viewer','researcher')`; no table rebuild is needed. `src/types.ts` `StaffRole`/`Permission` and the nav permission table gain the role; `actor_role` accepts `researcher`.
- **Why:** an IRB-style separation between teaching staff (who need names to teach and grade) and research analysts (who must not see identities and must only analyze consenting students) is the norm for learning-analytics studies; reusing `viewer` mixed the two.
