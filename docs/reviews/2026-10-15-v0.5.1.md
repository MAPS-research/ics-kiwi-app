## Findings and resolution

### High / P1 — Real instructor course payload was treated as a string ID

- Location: `scripts/local-kiwi/bridge/CssLabTeacherEntry.tsx`, `loadCssLabTeachingCourses`, originally the instructor list assignment before the normalization now at lines 13–23.
- Evidence: the running backend's `InstructorClassService.getClassesForInstructor` returns full Class objects (`instructorClasses.map(ic => ic.class)`). The generated frontend DTO declares `string[]`, but its JSON mapper preserves the actual array. Existing Kiwi `Classes.tsx` and `AdminLayout.tsx` already normalize object IDs.
- Failure: the original resolver passed an object as `classId` to the generated app-binding client. That client uses `encodeURIComponent(String(classId))`, producing `[object Object]`; a real instructor could remain on the retry screen. The initial six tests used string-only mocks and missed this.
- Recommendation sent: normalize actual `{ id }`, legacy `{ classID }`, and string entries, reject malformed identifiers, deduplicate, and test the real backend payload.
- Implemented resolution: explicit unknown-entry normalization and validation, plus contract tests.
- Independent retest: real object-payload case passed, as did the updated nine-test entry suite and the full-layout enabled-course cases. No actual instructor login or network request is claimed.

### High / P1 — Outer instructor navigation bypassed the new resolver

- Locations: installed `.local/kiwi-ui/src/pages/admin/AdminLayout.tsx`, generic classless instructor redirect and sidebar app-item `onClick`; maintained by `scripts/local-kiwi/frontend.mjs` compatibility patches.
- Failure: the actual router wraps `AdminAppPage` in persistent `AdminLayout`. Its existing classless-app effect selected `classOptions[0]` for every instructor app. Its global sidebar click performed the same selection. With an alphabetically first course A having Lab disabled and course B having Lab enabled, both paths chose A before the dedicated resolver could choose B. The effect could also override a multiple-course chooser. Tests that mounted only `AdminAppPage` did not cover the outer behavior.
- Independent reproduction before correction: full-layout DOM cases observed `Course: a-disabled` instead of `Course: b-enabled` for direct global entry and real sidebar callback; the multiple-course choice was also overridden to the first course.
- Recommendation sent: let the CSS Lab resolver own its classless route and global menu click, while retaining an explicitly selected course.
- Implemented resolution: the generic instructor redirect and first-assigned-course fallback now exclude `ics-r-lab`.
- Independent retest: actual `AdminLayout` and `AdminAppPage` effects passed direct global bookmark, sidebar callback, and multiple-enabled-course selection cases. Rendering-only TopNav/sidebar stubs retained the real layout's callbacks; the test did not exercise browser visuals or a real iframe.

### Medium / P2 — A previous admin UI lookup failure survived successful course entry

- Location: installed `.local/kiwi-ui/src/pages/admin/AdminAppPage.tsx`, asynchronous UI lookup effect and render state; maintained by `scripts/local-kiwi/frontend.mjs` patches.
- Independent reproduction: start `/admin/app/ics-r-lab/class/old-class`; fail the first app lookup; navigate through `/admin/app/ics-r-lab`; resolve a valid course and successful second lookup. The old `Failed to load app admin panel` alert remained and the teacher frame never mounted.
- Related risk: without cancellation and a resolved-scope guard, a late response from an old route could write stale UI/error state for a new route.
- Recommendation sent: clear request state when the scope changes, cancel old asynchronous writes, and prevent old metadata from rendering under a new scope.
- Implemented resolution: error/UI reset, cancellation checks, resolved-scope rendering guard, and a frame key containing app/course/UI identity.
- Independent retest: successful recovery from the old error passed. A separate delayed-old-request rejection after the good course opened also passed; the new course frame remained and no stale alert appeared.

## Intent and final code assessment

The change repairs the global registered teacher link `/admin/app/ics-r-lab`, which has no course ID, by selecting an enabled teaching course before creating a course-scoped Lab frame. One enabled course redirects automatically; multiple courses require a choice; no enabled courses or a failed lookup show an explanation/retry without a classless iframe. Standalone teacher access now points primarily to Kiwi sign-in, with the separate local demo key labeled explicitly. Lab initialization errors stop the spinner and offer retry; role entry waits for initialization.

Source checks found that the role endpoint returns the system role, and the resolver uses administrator listing only for `admin`, active instructor assignments for `instructor`, and no teaching choices for other roles. It uses the existing authenticated API clients and existing scoped admin path helper. SDK token minting and server authorization were not bypassed or weakened in the inspected fix. Those authorization paths were read for context, not accepted through a live browser test.
