## Visual review and difficulties

- At desktop, the top browser controls form a compact two-row panel above one editor. Labels, controls, chapter title and course-position controls were readable and contained.
- At 390px and 320px, Add/Save and picker controls wrapped into a vertical layout. Previous and Next stayed visible. The chapter editor fields and long heading wrapped within the card. Read-only DOM measurement of the Lab iframe body at 320px was `clientWidth: 320`, `scrollWidth: 320`.
- Native select values and single-line input text are clipped inside their own controls at narrow widths; the full selected chapter title is visible in the editor heading. No content escaped the Lab layout.
- Student role-entry card and teacher student-preview assignment cards were inspected at desktop and 390px. Navigation labels, card text and actions remained readable.
- The host floating-chat button can cover text near the lower viewport edge. That placement is controlled by Kiwi, not this App. No host UI patch was attempted.
- CUA iframe click/key helpers reported stale target or focus-root errors even when elements were visible. Fill/select operations worked; review used focus plus real host Tab/Shift-Tab/Return/Space to activate controls. This was an automation-control limitation, not counted as a product defect.
- Full host reload returned the student to the host course Materials tab; the reviewer reopened CSS Kiwi Lab and the assignment before checking persisted drafts. The App data persisted, but a host reload did not preserve the inner route.

## Findings and limits

No blocking defect was observed in the exercised chapter picker, save or regression paths.

| Severity | Observation | Status |

Untested limitations:

- No existing read-only staff account was available. Read-only staff browsing/edit prevention was not tested in the real host; the implementation agent reports unit coverage. Student denial of teacher access is a separate, observed result.
- Remove chapter, position-arrow reordering, file uploads, chapter-note editing, error-hint editing and package installation were not exercised this round. Search/sort preservation of existing order was exercised.
- Real contextual-chat model output and AI-generated questions remain unverified because the local host has no configured provider. Template practice is recorded separately.
- The exact SDK context payload and its consumption were not inspected at the network boundary. No SDK or host integration change was part of this version.
- Student receipt of the newly released grade was not reopened in the student account after release; teacher release state and Data Hub were observed. Cross-browser draft storage, concurrent edits and production accounts were not tested.
