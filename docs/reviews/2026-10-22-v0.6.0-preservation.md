# v0.6.0 migration preservation check — 2026-10-22

Spec §18 step 8 (INTEGRATION). The v0.6.0 server code migrated a **copy** of the live database; `data/kiwi-lab.sqlite3` itself was not migrated and not written.

## Method

1. A read-only online backup of the live file was taken with `sqlite3 'file:data/kiwi-lab.sqlite3?mode=ro' ".backup <scratch>/kiwi-lab.copy.sqlite3"`, plus a second untouched copy (`kiwi-lab.pristine.sqlite3`, sha256 prefix `e1a3621b0bccc130`).
2. `KIWI_DB_PATH=<copy> OPENAI_API_KEY= OPEN_AI_TEST_KEY= python3 preserve.py <repo>` ran `server.app.init_db()` twice on the copy. The scratch script lives next to the copy in the orchestration scratchpad (`v06/integ/preserve2/`). It refuses any path outside the scratchpad.
3. The script records counts of every table before and after, SHA-256 digests over the authored content, the migration and backup lists, the derived-index versions, the population per class, and `PRAGMA integrity_check` / `foreign_key_check`.
4. The automatic backup was compared with the pristine copy by `.dump`.

Live file fingerprint (mtime, size) before and after this work: `2026-10-22 00:39:27 PDT`, `503808` bytes, both unchanged. The read-only backups refreshed SQLite's `-shm` lock index next to it; the `-wal` file is still 0 bytes. The user's v0.5.1 API on port 8101 keeps serving the unmigrated file until it is restarted (README › Deploy v0.6.0).

The same code also passed FOUNDATION-10 on five snapshots (`KIWI_SNAPSHOT_DBS` = the evaluated `kiwi-lab.before-v0.6` and `kiwi-lab.before-eval` scratch snapshots, plus `.local/v0.4|v0.5|v0.5.1-before.sqlite3`). `python3 -m unittest -v server.test_core.MigrationTests` reported 10 OK, 0 skipped, and the snapshot sources' hashes were unchanged afterwards.
