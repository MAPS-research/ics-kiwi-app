## Visual review

Desktop teacher dashboard, grading, student list/card, question editor and role chooser were readable and contained. At 390px, teacher dashboard cards, student assignment cards and the question/practice editor stacked without observed text overflow. The corrected three-entry student/preview navigation remained fully visible at 320px. The host floating chat button sometimes overlays content near a viewport edge; the App does not control that host placement.

The first CUA iframe clicks and frame-scoped key actions failed with stale target/focus errors even though the controls were visibly present. Review proceeded with host focus plus real Tab/Shift-Tab/Return and text entry. This was an automation-control difficulty, not counted as a product defect. One CSS HMR update did not appear in the existing iframe; a full host reload loaded the final navigation styles.

## Untested limits

- No configured LLM provider: real model responses, quality and full contextual-chat behavior could not be accepted. Template practice is recorded separately from generated AI practice.
- The exact SDK context payload, clearing when navigating away, and exclusion of staff-only answer keys were not inspected at the browser/network boundary in this review. Implementation tests cover these separately; they are not treated as this reviewer observing a live AI request payload.
- Legacy `/student/kiwi`, old practice-chat bookmarks and read-only independent R draft recovery were not navigated inside the real host iframe. No stored legacy draft was seeded or modified for this review. Their unit coverage is not a real-browser pass.
- No package installation, file upload, plotting, large R workload, native Scratchpad-to-Lab code transfer, host native-history export, or cross-browser storage migration was tested.
- Dedicated local accounts and a new review assignment were used. Production authentication, real course accounts, existing large datasets and multiple concurrent students were not exercised.
