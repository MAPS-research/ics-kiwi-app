## 3. 代码审阅转交项及针对性验证

开发阶段另一个审阅 agent 在代码中识别出以下状态风险。下面不把这些项写成未修复版本的浏览器复现；此代理实际测试的是修复后的行为。

| 代码风险 | 本次实际验证范围 |
| --- | --- |
| `execute` 异步结束后未核对学生、题目和当前代码，旧 R 结果可能用于新代码的补全判定 | 自由补全题运行 `Sys.sleep(2)` 后立即改代码。结束后旧输出被丢弃；检查提示必须成功运行当前代码。重跑正确代码得到 `[1] 10` 后才判对。运行期间生成/检查按钮不可用 |
| `newQuestion` / `requestHint` 在 live AI 等待期间可能返回过期内容并覆盖新单元、题型、难度或身份 | 已加请求/上下文保护。**没有 Kiwi live AI 环境，本次未真实验证 AI 延迟返回**，不能写为 live 测试通过 |
| 载入最近运行代码、重置编辑器可能保留旧反馈或输出 | 在已判对后载入一条历史运行，答对反馈和控制台旧输出均消失；重置代码同样清空。`print(10)` 后 `stop("Review test error")` 的失败运行未被判为正确 |
| 桌面已处于 question 状态时，编辑器返回按钮仅设置相同 tab 值可能不触发滚动 | 第二次点击返回按钮的实际题卡顶部位置从 **-60.71 px→23.79 px**，滚动位置从 **377→292.5**，返回确实发生 |
| 切学生、单元、题型、难度或教师更新课程后旧题、代码、运行结果可能混合 | 运行 `Sys.sleep(2); print(111)` 中切到 Ada，题目清空、代码回到默认、无旧答案/提示/输出；晚完成的 111 未落入 Ada 页面。本次未修改课程设置，只验证了学生身份切换和本地单元/题型切换 |

主 agent 最后还将同类执行保护补到 `StudentWork`。稳定版本中，作业第二题运行 `Sys.sleep(2); print(4)` 时改成 `print(99)`；旧执行结束后 **输出面板数量为 0**，重新运行得到 **`[1] 99`**。随后恢复原代码草稿，没有再提交或改动已保存的 19/20 评分。
