# Changelog

## [0.6.0] - 2026-10-22

### Features
- **Teacher information architecture.** Seven sections (Home, Assignments, Grading, Students, Chapters & AI tutor, Insights, Course settings) with a global top bar: Find a student, a shared time range (Since last class / This week / …), Presentation mode, Preview as student. Old v0.5 URLs redirect (“That page moved”). Narrow screens get a menu drawer.
- **Home**: what needs action now (To grade, Ready to release, Missing with “started”, flagged AI replies), students needing attention with editable rules, what to re-teach on your own questions, what students asked the AI, and a this-week glance.
- **Assignments**: a four-section editor (Questions, Dates, Student help, Audience); late policies, open/close dates, attempt limits, timed homework; per-assignment tool policy (R workspace, Ask Kiwi help level, similar practice); in-class freeze after the first real attempt with revisions; drafts saved to the server; files per assignment/question (mounted into webR); starter assignments mapped to your chapters; Duplicate / Create revision / Close / Archive / Delete draft; **Preview as student**, with preview rows excluded from analytics and “Clear test submissions”. The Student help note and the assignment list state whether Ask Kiwi still protects a homework’s answers and until when.
- **Grading**: per-question scores and comments with rubric, auto-check pre-fill, auto late penalty, drafts then release (students see grades only after release), Save & next (Ctrl/⌘+Enter), history with who graded, integrity flags, latest-attempt queue with **To grade (n)** on the tab, gradebook states (Missing · started, Not due yet, newer attempt ungraded, `Released 18/20 · 1 submission`), Grades for LMS CSV, Student × assignment status CSV, in-class exercise Results with stuck students.
- **Chapters & AI tutor**: this week’s chapter, free-practice scope and per-chapter student access (Opens later / Review / Hidden); per-chapter R packages, datasets and AI-reference files; AI tutor rules as append-only versions (history, compare, restore, copy, reset to course default) per chapter and group; separate instructions for Ask Kiwi and generated practice; read-only platform rules with conflict lint; Test this rule (dry run and real) and saved checks.
- **AI runtime**: every reply is logged with provenance (`ai_calls`: policy version, model, prompt hash, instructions sent); a deterministic final-answer guard rewrites or redacts replies that leak protected homework answers; chapter access and the assignment’s help level are enforced by the server; generated practice is stored in full, checked by the server, shuffled, verified once without an oracle, with an unlock rule and a daily limit; local guidance and templates without an AI key; bounded provider concurrency and per-address limits.
- **Telemetry**: a durable client outbox (persist, retry with backoff, batch, keepalive), server-side validation with head+tail truncation instead of rejection, deduplication by `eventId`, server-written answer/AI events, heartbeat accounting per 30 s bucket, attribution columns, an R runtime with autoprint, plots, structured output, allowlisted package installs and chapter dataset mounting, native Kiwi projection v3 (thumbs/flags, all AI responses, revisions), and a **Data health** page with outage periods.
- **Insights**: Activity explorer with one filter-chip row, Teaching/Research column presets, Origin and Work filters and folded AI items; question activities; answers by question; student × assignment and full activity timelines; AI conversations digest and coding mode; Course metrics with denominators, trends and learning curves; group filters everywhere.
- **People and governance**: roster with research consent, exclusions and CSV import (preview → apply), groups (sections, conditions, cohorts, seeded randomization, history), student profiles, staff keys and four staff roles (instructor, TA, viewer, researcher), Kiwi staff overrides, privacy settings, audit log viewer, anonymize/delete with tombstones, retention, and exports (activity, AI conversations, generated items, coded conversations, one student’s case file, research package with codebook and manifest), course packages and a 12-chapter SOCS-SH 190 course template built from the real Spring 2026 course materials.
- **Tooling**: `npm run test:server`, `npm run test:bridge`, `npm run coverage` (frontend line coverage with `@vitest/coverage-v8`, dev only); `server/test_integration.py` (builders vs real writers, change requests, wiring); static naming lint and accessible-name scan; `scripts/local-kiwi/reinstall-bridge.mjs`.

### Design Rationale
- **Server-owned truth.** Correctness, AI provenance and grades are written by the server (P2); the browser only reports what it saw. This is what makes accuracy, “AI reply may contain the final answer” and the research exports trustworthy, at the cost of a stricter event contract for old clients.
- **Additive, versioned data.** Every schema change is an added column or table; payloads are never rewritten (mapping tables, `event_revisions`, truncation flags). Rules, assignments and native projections are versioned so an analysis can name the version it used.
- **Population at query time.** Who counts (enrolled, non-excluded, non-staff, non-preview) is decided when a number is computed, so roster fixes apply retroactively without touching events.
- **Deterministic guard before model trust.** Leak detection uses containment matching and explicit rules with false-positive fixtures instead of a second model call: reproducible, testable and cheap; paraphrases without shared 3-grams remain a documented miss.
- **Fail closed for standalone access.** No default teacher key; demo sessions are signed; student writes need a registered course.
- **Protection for the assessment window, not forever** (owner decision D2). Once a homework closes, worked solutions and AI explanations help students learn, so new homework stops protecting answers at close. Teachers who reuse items choose `Never` deliberately, and the editor states the consequence.
- **Researchers never see identities** (D3). Teaching staff need names to teach and grade; research analysts work on pseudonymized data from consenting students only. A separate `researcher` role enforced by the server keeps the two apart, instead of overloading `viewer`.
- **Trade-offs taken:** legacy v0.5 endpoints stay for one release so cached bundles keep working; the trust model for Kiwi identity is unchanged pending the maintainers’ answers (below).

### Notes & Caveats
- **Owner-only data files (2026-10-23):** a `data/` directory or SQLite database the API creates is now 0700/0600 (SQLite gives `-wal`/`-shm` the same mode); existing directories and files keep their modes, so run `chmod 700 data && chmod 600 data/kiwi-lab.sqlite3*` once on an existing install (README › Operations, runbook §6.7).
- **Final orchestrator fixes (2026-10-23):** Course metrics' per-active average counts learning actions, matching its *Active* denominator (label "Avg. learning actions per active student"); the revision-draft copy notice survives a repeated load; timeline exercise names are unique; grading filter placeholder no longer clipped.
- **Owner decisions D1–D7** of 2026-10-22 and **D8** of 2026-10-23 ([decisions](docs/handoff/v0.6.0-decisions.md)) settle the spec’s open product questions and override the spec where they differ. The notes below follow them.
- **Migration and backup.** The first start of v0.6.0 migrates `data/kiwi-lab.sqlite3` and first writes an online backup to `data/backups/kiwi-lab.pre-0.6.0-001-columns-<UTC timestamp>.sqlite3` (startup stops if the backup fails). Verified on a copy of the live database: no assignment, submission, grade, feedback, chat turn, policy or event payload changed ([preservation review](docs/reviews/2026-10-22-v0.6.0-preservation.md)). Rollback: stop the servers and restore that backup over `data/kiwi-lab.sqlite3`.
- **Session re-index and aliases.** Question activities are re-indexed (`sessions-v3`: no browser tab in the key, so tabs merge); old session links keep working through `learning_session_aliases` and open the re-indexed activity with a notice.
- **Legacy endpoints until v0.7.** The v0.5.1 endpoints listed in spec §6.9 are kept and routed to the new implementations for this release only; `PUT /api/teacher/policies` logs a deprecation warning and creates a new rule version.
- **Default free-practice scope.** New and migrated courses use “Current and earlier chapters”: later chapters show “Opens later” in student practice. Change it in Chapters › Free practice scope.
- **Default homework tool policy for new work.** New homework starts with R workspace on, Ask Kiwi “hints only”, Run disabled for Predict output, and similar practice off. Existing assignments keep the v0.5 tool access they had.
- **Homework answers are protected while students can still submit** (D2). New homework defaults to `Solutions visible: After the due date`, so protection ends when the homework closes, that is, once no student can submit any more (after the due date, or after the late window when late work is accepted). New homework accepts late work for 7 days after its due date by default (D2 addendum), so it closes on its own; a homework that accepts late work with no end date stays protected until a closing date is set or it is archived, and the editor says so. `Never` keeps answers protected until the homework is archived or the setting changes, which is useful for items you will reuse. Migrated v0.5 homework keeps the value the migration gave it. While protected, Ask Kiwi and similar practice will not give the final answer, and explanations of homework-derived practice are withheld. `After the due date` now also waits for the late window: solutions appear once the homework closes, so a late submitter never sees them first (before, they appeared at the due date even while late work was still accepted). The editor’s Student help note and each published homework row in the assignment list show the actual state, e.g. `Ask Kiwi won't give final answers until this homework closes (Sat 10/24 23:59 + late window to Mon 10/26 23:59).`, `… (Solutions visible: Never).`, `Answers are no longer protected: this homework is closed.`, or the no-closing-date case.
- **Standalone hardening and new environment variables.** `KIWI_TEACHER_KEY` has no default (unset = the standalone teacher workspace answers 503 `teacher_key_not_configured`); key failures are rate-limited; demo students use signed sessions or teacher-issued `#demo=` links. New: `KIWI_STANDALONE_CLASS_IDS`, `KIWI_MODEL_ALLOWLIST`, `KIWI_AI_CONCURRENCY`, `KIWI_AI_QUEUE_WAIT_S`, `KIWI_AI_PER_IP_PER_MINUTE`, `KIWI_SERVER_OWNED_EVENTS`, `KIWI_GIT_SHA` (see `.env.example`). `scripts/local-kiwi/config.mjs` no longer writes the `kiwi-local-demo` fallback key.
- **Roles.**
  - Kiwi course assistants become Lab TAs (D1): they can grade and view Insights; they cannot edit assignment questions, AI tutor rules or settings. Instructors can override any Kiwi staff member’s Lab role in Course settings › Staff & roles.
  - Analytics-only Kiwi staff are viewers: their exports are always pseudonymized and consent-filtered, and they cannot download named case files (a narrowing of v0.5.1).
  - The new **researcher** role (D3) opens Insights, reads chapters, AI tutor rules and groups without editing them, and exports research data. The server shows researchers pseudonyms only, whatever the client’s name mode. Every researcher export is pseudonymized, consent-filtered and limited to verified identities; case files are refused. Researchers cannot grade, edit, manage people or preview as a student, and every data access they make is logged with the role (`data_access_log.actor_role='researcher'`; reads of routes without an audit category are logged as `read`). Assign the role with a staff key (standalone) or a Staff & roles override on a Kiwi staff member (Kiwi-linked); no Kiwi role becomes researcher automatically.
  - How it is enforced: a new permission `viewStudents` (named teaching views: Home action lists, roster, Needs attention, profiles, student search, gradebook, exercise results, per-assignment student lists, re-teach marks) goes to instructors, TAs and viewers but not researchers; staff routes without a permission stay closed to researchers unless listed (time range, settings, Kiwi status/sync, codebook). Researcher responses are relabeled to pseudonyms, emails are nulled, and roster names and emails inside free text (prompts, replies, AI call details) are replaced with the pseudonym. The researcher’s sidebar shows Groups, Chapters & AI tutor and Insights; Home opens the Activity explorer; Presentation mode is locked on.
  - The `staff.role` CHECK of the 0.6.0 DDL allows `researcher`. It was edited in place because no live database had run an earlier 0.6.0 build. A scratch database created by a pre-release build should be re-created from its backup.
- **Staff must use Preview as student.** A staff identity calling a student route without preview gets 403 `preview_required`; preview rows are stamped `is_preview=1` and excluded from every count.
- **Legacy v0.5 auto-checks** are re-judged with `judging-v2` (case, quotes and whitespace now matter); checks that cannot be re-judged (the assignment changed after the attempt) are excluded from Auto-checked accuracy and shown separately as “Legacy auto-check (v0.5 rules)”.
- **Server-owned events enforced (cut-over).** `event_schema.SERVER_OWNED_MODE` defaults to `enforce`: v2 client copies of server-owned types (`answer_submitted`, `ai_question`, `question_generated`, …) answer 422 `server_owned_event`; a v1 (v0.5.1 client) `answer_submitted` is stored as `checked_by='client'` and never counted. `KIWI_SERVER_OWNED_EVENTS=accept` restores the transitional behavior.
- **Local Kiwi demo host patches** (approved for the local demo, D5).
